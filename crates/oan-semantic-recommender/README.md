# OAN Semantic Recommender

Shared advisory recommender for OAN registration and discovery UX.

This crate is intentionally not an authority. It recommends canonical
authorized-domain IDs, capability tags, resource type hints, and protocol hints
from Chinese, English, or mixed-language text. Registrar and Discovery nodes
remain responsible for HTTP APIs, current authorization scope, validation,
governance state, and final trust decisions.

Current boundaries:

- no mandatory database dependency;
- no `pgvector` dependency;
- no external LLM or translation service;
- canonical authorized-domain IDs remain English OAN protocol values;
- Registrar registration suggestions must be filtered by the Registrar's
  effective authorized-domain scope;
- Discovery query suggestions are optional search assistance and do not change
  resource trust filtering.

Primary APIs:

- `SemanticRecommender::suggest_registration_metadata(...)`
- `SemanticRecommender::suggest_discovery_query(...)`
- `normalize_capability_tags(...)`

The embedded authorized-domain taxonomy is copied from the OAN
authorized-domain taxonomy snapshot and augmented with bilingual recommendation
profiles. Capability-tag suggestions come from
`data/capability_tag_tree.v1.json`, a cleaned AgentTaxo-9K-derived tree that is
independent from authorized domains.

Scope semantics:

- `["*"]` means the calling node covers every authorized domain.
- `[]` means the calling node covers no authorized domain.
- invalid scope entries are ignored and reported in `warnings`.
- registration results split selectable domains from out-of-scope hints.
- discovery results only return domain hints covered by the Discovery node.

The helper `normalize_capability_tags` canonicalizes user-entered tags into
stable lowercase kebab-case values and removes duplicates. It is useful for
website chip inputs and node-side request cleanup, but it does not validate
business meaning or authorize any resource.

Capability tag tree:

- generated by `tools/generate_capability_tag_tree.py`;
- source: AgentTaxo-9K, ODC-ODbL-1.0;
- parent tags are AgentTaxo top-level folders;
- child tags are cleaned JSON `Tags` values under each parent;
- child tags with `sourceCount < 5` are excluded;
- broad tags that appear under at least 20 parent tags are moved to the
  `cross-cutting` parent instead of being copied under every source parent;
- no authorized-domain mapping or hints are generated.
